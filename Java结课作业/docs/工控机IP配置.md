# 每台工控机 IP 配置说明

> 目标：让每台运行监控客户端的工控机都使用 `172.20.205.0 ~ 172.20.224.255` 内的地址，并在连接时绑定自己的源 IP。

## 1. 先理解程序能做什么

程序**不会修改操作系统网卡配置**。它做两件事：

1. 客户端连接前校验网关 IP 和本机 IP 是否在允许范围；
2. 在【本机IP】或 `--local-ip` 填写地址时，通过 `Socket.bind()` 绑定该源地址。

因此：

- 每台工控机的静态 IP 仍需要在操作系统中设置；
- 程序会把“本机实际源 IP”显示在连接状态里，并拒绝不在范围内的源地址；
- 网关端不需要逐台配置客户端 IP，`clients` 命令会显示每个客户端的远端 IP。

## 2. IP 规划示例

`172.20.205.0 ~ 172.20.224.255` 属于 `172.20.0.0/16` 的子集，建议统一使用子网掩码 `255.255.0.0`。

| 角色 | 示例 IP | 说明 |
| --- | --- | --- |
| 网关/边缘工控机 | `172.20.205.10` | 运行 `mine-gateway`，可绑定 `0.0.0.0` |
| 工控机 PC-01 | `172.20.205.11` | 运行一个客户端 |
| 工控机 PC-02 | `172.20.205.12` | 运行一个客户端 |
| 工控机 PC-03 | `172.20.205.13` | 运行一个客户端 |
| 工控机 PC-04 | `172.20.205.14` | 运行一个客户端 |
| 交换机/路由 | `172.20.205.1` | 如有网关设备则填写，没有可留空 |

每台工控机一个 IP，不要重复。客户端本身可以留空【本机IP】，让系统使用该网卡的源地址；但为了演示“每台一个明确 IP”，推荐显式填写。

## 3. 操作系统设置静态 IP

> 以下命令需要管理员/root 权限，且网卡名称（`以太网`、`en0`、`Wired connection 1`）要换成实际名称。修改前请确认不会影响远程连接。

### Windows

图形界面：`设置 → 网络和 Internet → 以太网 → IP 分配 → 编辑 → 手动 → IPv4`，填写：

- IP：`172.20.205.11`
- 子网掩码：`255.255.0.0`
- 网关：`172.20.205.1`（如网络中没有网关可留空）
- DNS：按学校网络要求填写

命令行（管理员 CMD/PowerShell）：

```bat
netsh interface ipv4 set address name="以太网" static 172.20.205.11 255.255.0.0 172.20.205.1
```

查看结果：

```bat
ipconfig
```

### macOS

图形界面：`系统设置 → 网络 → 以太网 → 详细信息 → TCP/IP → 手动`，填写 IP、子网掩码 `255.255.0.0` 和路由器。

命令行（临时设置，重启可能失效）：

```bash
sudo ifconfig en0 inet 172.20.205.11 netmask 255.255.0.0
```

查看结果：

```bash
ifconfig en0 | grep "inet "
```

### Linux（NetworkManager）

```bash
nmcli connection modify "Wired connection 1" ipv4.method manual \
  ipv4.addresses 172.20.205.11/16 ipv4.gateway 172.20.205.1
nmcli connection up "Wired connection 1"
ip -4 addr show
```

## 4. 启动网关并做网络预检

### 4.1 启动网关

在网关电脑上：

```bash
./run-gateway.sh --host 0.0.0.0 --port 8888
```

也可以绑定具体地址：

```bash
./run-gateway.sh --host 172.20.205.10 --port 8888
```

`0.0.0.0` 会监听所有网卡，适合课堂多机演示；控制台会打印可连接的局域网地址。

### 4.2 在每台客户端电脑上预检

网关启动后，先不要打开 GUI，在**客户端电脑**的项目目录执行：

```bash
./check-network.sh --host 172.20.205.10 --port 8888 --local-ip 172.20.205.11
```

Windows：

```bat
check-network.bat --host 172.20.205.10 --port 8888 --local-ip 172.20.205.11
```

预检会依次检查：

1. 网关 IP 与本机 IP 是否在允许范围；
2. 本机 IP 是否真的配置在已启用网卡上（会列出本机所有 IPv4）；
3. 是否能用该源 IP 建立 TCP 连接；
4. 是否收到心跳 ACK、CRC 是否正确。

成功输出：

```text
[OK] TCP 已连接，实际源 IP = 172.20.205.11，远端 = /172.20.205.10:8888
[OK] 心跳 ACK 成功，已接收 1 帧，CRC错误=0
[PASS] 网络预检通过，可以启动 GUI 客户端。
```

失败时按 `[FAIL]` 提示处理，最常见的是本机 IP 未配置或 IP 填错。预检不通过时启动 GUI 也会失败，先修网络。

## 5. 每台工控机启动客户端

### 方式 A：GUI 填写

在每台机器启动客户端，填写：

- 网关 IP：`172.20.205.10`
- 端口：`8888`
- 本机IP：该工控机自己的地址，例如 `172.20.205.11`
- 点击【连接网关】

连接成功后，顶部状态会显示：

```text
网关连接成功 172.20.205.10:8888 · 本机 172.20.205.11
```

### 方式 B：命令行（推荐批量演示）

```bash
# 参数：本机IP  网关IP  端口
./run-client-pc.sh 172.20.205.11 172.20.205.10 8888
```

Windows：

```bat
run-client-pc.bat 172.20.205.11 172.20.205.10 8888
```

或者直接使用通用启动参数：

```bash
./run-client.sh --host 172.20.205.10 --local-ip 172.20.205.11 --auto-connect
```

### 方式 C：留空本机 IP

如果操作系统已经给网卡配置了 `172.20.205.11`，且路由正确，可以把【本机IP】留空：

- 客户端自动使用系统源地址；
- 状态栏会显示实际源 IP；
- 如果实际源 IP 不在允许区间，客户端会拒绝连接并提示。

## 6. 验证每台 IP 是否生效

预检通过后，在网关控制台输入：

```text
gateway> clients
```

应看到类似：

```text
客户端#1 /172.20.205.11:52100 已发送=...
客户端#2 /172.20.205.12:52102 已发送=...
客户端#3 /172.20.205.13:52104 已发送=...
```

客户端状态栏/连接日志也会显示“本机 172.20.205.x”。

## 7. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `本机工控机 IP 172.20.205.11 绑定失败：Cannot assign requested address` | 该 IP 未配置在网卡上，或填写了别的机器的 IP | 先在操作系统配置静态 IP，或清空【本机IP】 |
| `本机源地址 10.x.x.x 不在允许范围` | 系统源地址不在实验网段 | 给网卡配置该区间静态 IP，或在【本机IP】填写已配置的地址 |
| `该 IP 不在允许范围内：仅允许 172.20.205.0 ~ 172.20.224.255` | 网关 IP 填错 | 填网关电脑的实际实验网段地址 |
| 能连上但收不到数据 | 网关未启动/端口错误/防火墙 | 检查网关进程、端口和 8888/TCP 入站规则 |
| 两台机器 IP 相同 | 手工配置冲突 | 每台工控机使用唯一 IP |
| 客户端一直“自动重连中” | 网络不通或网关未监听 | `ping` 网关、检查交换机/防火墙 |

## 8. 说明

- 本程序**不修改系统网络配置**，只做地址校验和源地址绑定；静态 IP 由每台工控机的操作系统设置。
- 一台电脑如果要模拟多个工控机客户端，需要给同一网卡配置多个 IP 别名，并让每个客户端用不同的 `--local-ip` 启动；真实课堂演示建议一台机器一个客户端。
- `172.20.205.0 ~ 172.20.224.255` 是一个跨 20 个 C 段的地址范围；统一使用 `255.255.0.0` 掩码即可让它们处在同一 `172.20.0.0/16` 广播域内，是否互通仍取决于交换机、VLAN 和路由配置。

## 9. 虚拟机 + 主机双机演示拓扑（推荐）

可以用“虚拟机跑网关、主机跑监控终端”的方式，但必须先分清程序角色：

| 角色 | 运行的程序 | 示例 IP | 客户端里填在哪里 |
| --- | --- | --- | --- |
| 井下边缘网关/工控机 | `GatewayServer`（`run-gateway.sh`） | `172.20.205.10` | 客户端的【网关 IP】 |
| 监控终端/上位机 | `MainClient`（`run-client.sh`） | `172.20.205.11` | 客户端的【本机IP】 |

也就是说，**VM 的地址是网关目标地址，主机的地址是终端源地址**。两者都必须在 `172.20.205.0 ~ 172.20.224.255` 内（或者本机调试使用 `127.0.0.1`）。

### 9.1 网络模式：不要用 NAT

- **NAT**：主机不能主动访问 VM 的 `172.20.x` 地址；端口转发只能映射到 `127.0.0.1:8888`，客户端会把它当成 localhost，不能真实验证工控机 IP。
- **Host-only（推荐）**：主机和 VM 在同一个虚拟网段，不需要真实交换机，适合笔记本单机演示。
- **Bridged（桥接）**：VM 直接接到真实局域网，需要实验室网络允许 `172.20.205.x` 地址并避免冲突。

### 9.2 Host-only 配置示例

以 `172.20.205.0/24` 为例（在允许范围内）：

```text
主机 host-only 网卡：172.20.205.11 / 255.255.255.0
虚拟机 VM 网卡：    172.20.205.10 / 255.255.255.0
```

VirtualBox：

1. `文件 → 主机网络管理器 → 创建`；
2. IPv4 地址设为 `172.20.205.11`，掩码 `255.255.255.0`，关闭 DHCP（或设置不冲突的地址池）；
3. VM 设置 → 网络 → 网卡 1 → 连接方式选择 `仅主机（Host-only）`；
4. 在 VM 的操作系统里把网卡设为 `172.20.205.10/24`。

VMware Fusion：

1. `虚拟机 → 设置 → 网络适配器 → 仅主机`；
2. 在虚拟网络编辑器中把 host-only 网段设为 `172.20.205.0/24`，主机侧地址 `.11`；
3. VM 内网卡设为 `.10/24`。

### 9.3 启动顺序

VM（网关）：

```bash
./run-gateway.sh --host 0.0.0.0 --port 8888
```

主机（终端）先预检：

```bash
./check-network.sh --host 172.20.205.10 --port 8888 --local-ip 172.20.205.11
```

看到 `[PASS]` 后启动：

```bash
./run-client-pc.sh 172.20.205.11 172.20.205.10 8888
```

如果主机 host-only 网卡配置的地址是 `172.20.205.1`，就把上面命令中的 `.11` 换成 `.1`；关键是【本机IP】必须等于主机网卡实际地址。

### 9.4 如果反过来：主机跑网关、VM 跑终端

也完全可以，只要角色对调：

```text
主机（网关）：172.20.205.10  →  ./run-gateway.sh --host 0.0.0.0
VM（终端）：  172.20.205.11  →  ./run-client-pc.sh 172.20.205.11 172.20.205.10 8888
```

VM 需要能显示 Swing 桌面；如果是无图形界面的服务器版 Linux，只能跑网关，不适合跑客户端。

### 9.5 多台工控机终端

- 一个网关 VM（`.10`）可以接多个客户端；
- 每个客户端 VM/物理机使用唯一地址 `.11`、`.12`、`.13`；
- 每个客户端都填写网关 `.10` 和各自的本机 IP；
- 网关控制台 `clients` 能看到不同的远端 IP。

### 9.6 检查顺序

1. VM 内 `ip addr` / `ifconfig` 能看到 `172.20.205.10`；
2. 主机 host-only 网卡能看到 `172.20.205.11`；
3. 主机 `ping 172.20.205.10`（被禁 ping 时跳过）；
4. VM 防火墙放行 `8888/TCP`；
5. 运行 `check-network.sh`，必须 `[PASS]`；
6. 再启动 GUI。
