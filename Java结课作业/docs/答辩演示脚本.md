# 答辩演示脚本（约 6 分钟）

> 建议提前打开两个终端：终端 A 运行网关，终端 B 运行客户端。所有命令都可直接复制。

## 0. 开场（20 秒）

“老师好，我的项目是《基于 TCP 与 Java 并发的智慧矿山瓦斯抽采多传感器监控仿真系统》。系统由两个独立程序组成：仿真井下边缘网关和带 Swing 看板的上位机客户端。技术上覆盖 TCP Socket、自定义二进制报文与 CRC、线程池、阻塞队列、ConcurrentHashMap、读写锁、Swing EDT 线程安全。”

## 1. 启动网关（40 秒）

```bash
./build.sh
./run-gateway.sh
```

讲解点：

- 网关默认绑定 `127.0.0.1:8888`，局域网演示可用 `--host 0.0.0.0`。
- 客户端只允许连接 `172.20.205.0 ~ 172.20.224.255`，本机联调额外允许 `127.0.0.1`。
- 每台工控机在【本机IP】填自己的地址（如 `172.20.205.11`），客户端会绑定该源 IP；留空则自动使用系统地址。
- 4 路虚拟传感器各自一个线程，用 `CyclicBarrier(4)` 对齐到同一采样时刻。
- 控制台可以输入 `help` 查看故障演练命令。
- 默认 500ms 采样，每轮产生瓦斯、负压、流量、温度 4 帧。

## 2. 客户端连接（40 秒）

```bash
./run-client.sh
```

输入 `127.0.0.1`、`8888`，点击【连接网关】。

真实工控机演示前，先在客户端执行：

```bash
./check-network.sh --host 172.20.205.10 --port 8888 --local-ip 172.20.205.11
```

看到 `[PASS]` 再启动客户端。

讲解点：

- 点击连接后，界面没有卡住，因为连接请求被放到后台线程。
- 客户端网络线程只做 TCP 读取、基于 `0xAA55` 的拆包和 CRC 校验，不碰 Swing。
- 合法帧进入 `LinkedBlockingQueue(5000)`，业务线程池消费。
- 表格每行是一个 `DeviceSnapshot`，来自 `ConcurrentHashMap` + 每设备读写锁。

## 3. 展示实时看板（40 秒）

指出：

- 4 个指标卡：在线设备、当前瓦斯、活动告警、接收报文。
- 曲线是纯 Java2D 绘制，最近 60 秒，有阈值线和危险区。
- 巷道图把 4 个测点映射到井下示意，绿色正常、红色告警、灰色离线。
- 底部管线状态显示线程池大小、队列、CallerRuns 和告警待发。

## 4. 模拟瓦斯事故（70 秒）

点击【模拟瓦斯事故】。

讲解点：

- 客户端发送 `0x81` 指令帧，网关解析后让瓦斯传感器按“爬升 2.5s → 保持 9s → 回落 7s”变化。
- 网关回 ACK，参数面板显示“网关应答 · 指令执行成功”。
- 瓦斯越过 1.00% 后，表格变红、曲线穿过阈值、告警日志出现红色“严重”、浮窗和提示音。
- 告警是**边沿触发**：持续超限只记一次，恢复才记一次，避免每帧刷屏。
- 演示【解除事故】，观察浓度回落和绿色恢复记录。

## 5. 断线重连（70 秒）

在网关终端执行：

```text
gateway> disconnect
```

讲解点：

- 客户端读循环退出，设备立即标记离线，状态变为橙色“自动重连中”。
- 后台按 1→2→3→5 秒退避重连；`generation` 原子代际防止旧线程覆盖新连接。
- 网关仍监听，客户端几秒内自动恢复绿色，数据继续。
- 也可以直接关闭网关进程，再重启，效果相同。

## 6. 参数下发与导出（40 秒）

- 参数面板：把瓦斯阈值改成 1.20，点击【下发阈值】；观察表格阈值即时变化，网关回 ACK。
- 全局采样周期改为 200ms，数据明显加快，展示高频下界面不卡顿。
- 点击【导出 CSV】，保存告警记录，说明后台线程导出 + UTF-8 BOM。

## 7. 收尾（30 秒）

“整个系统把网络 IO、并发处理、界面渲染彻底分层：网络线程只做 IO 和校验，业务线程池做解析与告警，EDT 只做渲染。项目还提供了 3 个自检程序，覆盖协议、并发、真实 TCP 联调、脏报文和断线重连，当前 92 项检查全部通过。”

## 8. 备份方案

如果虚拟机没有窗口标题栏，点击右上角【退出系统】（或按 `Ctrl+Q` / `⌘Q`）即可安全关闭客户端，不必强行关闭虚拟机。

如果现场网络/端口异常：

1. 直接展示 `docs/screenshots/` 中的三张真实运行截图。
2. 运行 `./run-tests.sh`，用自动化测试证明协议和重连逻辑。
3. 网关换端口：`./run-gateway.sh --port 9000`，客户端同步修改端口。
4. 本机防火墙拦截时优先用 `127.0.0.1`。

## 9. 高频问答

**Q：为什么不用 `HashMap`？**  
A：多个业务线程会并发写设备表，`HashMap` 可能结构损坏或抛 `ConcurrentModificationException`；`ConcurrentHashMap` 提供分段/CAS 并发安全，读性能也更好。

**Q：既然有了 ConcurrentHashMap，为什么每个设备还要读写锁？**  
A：Map 只保证“键值对本身”安全，不能保证一个设备的 value/threshold/online 多个字段的一致性。读写锁让一次快照读取看到一致状态；读多写少场景比 `synchronized` 吞吐更高。

**Q：为什么用阻塞队列，不用直接线程池提交？**  
A：网络生产和业务消费速度不一致，队列起到削峰和缓冲作用；有界容量防止 OOM。线程池队列只承担业务任务排队，两层队列职责不同。

**Q：为什么线程池 core=3、max=5？**  
A：4 路传感器、默认 8 帧/秒，3 个核心线程足够；短时突发扩到 5 个；队列 256 满后 CallerRunsPolicy 形成反压，避免任务无限堆积。

**Q：为什么同一设备要串行？**  
A：线程池并发完成顺序不确定，同一测点的旧帧可能后完成。按设备串行 + 时间戳单调校验，避免旧值覆盖新值和告警回退；不同设备仍然并行。

**Q：为什么 GUI 更新一定要 invokeLater？**  
A：Swing 组件不是线程安全的，只允许 EDT 访问。网络/业务线程直接调用可能随机崩溃、闪烁、死锁。统一 `SwingUtilities.invokeLater` 把 UI 任务投递到 EDT。

**Q：TCP 粘包/半包怎么处理？**  
A：`PacketStreamDecoder` 缓存半包，查找 `AA55`，凑够 19 字节后 CRC；CRC 失败只前移 1 字节重新找帧头，保证后续合法帧还能被解析。

**Q：断线怎么检测？**  
A：读循环 EOF/IOException；心跳每 3 秒；12 秒没有有效帧判定超时；关闭 Socket 唤醒读线程，监视线程退避重连。

**Q：连接状态怎么防止重复点击？**  
A：`AtomicBoolean running` + `generation` 代际；重复 start 直接返回 false，stop 自增代际使旧监视线程失效。

**Q：为什么用 CRC16 而不是 MD5？**  
A：CRC16 是工业报文常用的轻量完整性校验，2 字节开销、实现简单、能高效发现传输位错误；MD5/SHA 更重，适合安全场景而非帧级校验。

**Q：如果传感器数量增加到 1000 个怎么办？**  
A：当前 `ConcurrentHashMap`、线程池和队列可扩展，但固定 19 字节协议和单机 Swing 表格不适合千级；需要协议分页/批量、Netty、时序数据库、前端虚拟列表，并对告警做聚合。

**Q：每台工控机的 IP 是怎么设置的？**  
A：每台机器的操作系统先配置 `172.20.205.x ~ 172.20.224.x` 静态 IP；客户端有【本机IP】字段，连接时用 `Socket.bind()` 绑定该源地址，网关 `clients` 能看到不同远端 IP。程序不修改系统网络配置；本机演示可留空或填 `127.0.0.1`。详见《工控机 IP 配置》。

**Q：为什么限制 172.20.205～172.20.224？**  
A：这是课程实验网段。客户端在连接前做 IPv4 解析与无符号 32 位区间比较，避免误连其他网段；同时保留 `127.0.0.1/localhost` 让单机演示不受影响，网关的绑定地址不限制，仍可监听 `0.0.0.0`。

**Q：项目最大的难点？**  
A：三层线程边界：网络线程不能做业务、业务线程不能碰 UI、EDT 不能阻塞；再叠加 TCP 拆包与断线重连状态机。通过接口解耦、队列、invokeLater 和代际控制把边界固定下来。
